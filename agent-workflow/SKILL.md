# 聊天内协作入口

用户描述目标，主 Agent 管理工作。此入口在本项目由根 AGENTS.md 引用；不是后台服务，也不会修改已安装插件的调用策略。

## 先选最少路线

读取有关项目约定、现有成果与验收条件，沿用用户已确认的信息。开发任务继续使用当前可用的 `engineering-workflow-guide`；本文件补充协作与证据管理，不再生成一套重复规格。

| 目标 | 路线 |
|---|---|
| 新 UI、重大改版、仅设计不编码 | `ui-discovery` → `ui-ux-pro-max`；复用已有 Brief，执行适合任务的本地设计查询，检查实际交付 |
| 明确的局部样式/文案变更 | 检查并直接修改受影响部分，不重做访谈或派一组 Agent |
| 业务功能、跨模块开发 | 选一套主规格/执行流程，Ponytail 约束复杂度，按验收用例实现 |
| 故障修复 | 一套诊断流程；复现、根因、修复、原场景回归 |
| 视频制作 | 根 AGENTS.md 的视频路线与原 pipeline/tutorial；保持单一总时轴、真实看图/听审 |
| 文档、PPT、表格、图片、外部软件 | 当前可用的专门技能；按领域验收，不强套代码开发流程 |

按会话提供的真实路径解析技能并读取正文，记录所选来源与理由。同名不同源只选适合当前任务的一份；不要把缓存版本写成永久路径。只读当前阶段需要的引用。仅显式调用的入口不加入自动候选；文件存在、技能可见、工具已连接和业务成功分别核实。

小任务直接做并说明验证。出现两个以上可独立交付的工作、需要独立 reviewer，或需要恢复/反复修复时，读取 [协作协议](references/protocol.md)，建立本次运行记录。

## 主 Agent 的职责

- 根据交付目标定义可观察的验收条件、检查命令或领域检查；这些由主控确定，不能由实现者事后选一个永远成功的命令替代。
- 有独立工作才并行。一个共享文件只有一个写入者；主控写台账、整合跨任务改动。使用宿主本轮真实提供的子 Agent 工具与容量。
- 给执行者目标、输入、文件范围、约束和验收标准。给独立 reviewer 实际文件和参考，不先提供“已经正确”的结论。实际派发的身份写入记录。
- 主动回收结果，发现问题交给原执行者修复，复查受影响部分；默认最多两次修复。工具或账号缺失时保留可继续入口，不把未验项标通过。
- 交付前运行证据检查并核实用户目标。工具退出 0、生成任务被接收、文件存在、技术 QC 通过均不能独自代替最终验收。

## 恢复与改进

在当前聊天内监督；关闭聊天不承诺继续运行。恢复时读取本次状态、事件、尝试和证据，重新核对指纹，不能只看旧 complete 行。外部结果未知时先查已有任务 ID，不盲目再次提交。

收尾记录实际失败、漏路由或返工原因；能稳定复现的问题形成一项规则改进和回归场景。项目范围内按当前授权修改、复查并比较结果，保留回退依据；不要为提高通过率放宽验收、权限或删掉失败测试。稳定规则才推广到其他项目。

本入口不扩大用户的外部操作授权；既有授权继续有效，不为例行子任务重复询问。实现上的小决定由主控解决，只有会改变用户目标且无法推断的缺口才提问。
