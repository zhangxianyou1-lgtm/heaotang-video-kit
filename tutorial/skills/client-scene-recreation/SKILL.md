# 客户项目画面复刻

把文稿需要、但客户不允许拍摄的场景做成可直接剪辑的照片、界面截图和操作录屏。以真实业务界面和真实采集设备为视觉标准；追求尽可能接近参考的结果，不能把“100%相同”当成未经验证的完成结论。

## 当前任务范围与画面偏好

采用用户提供的复刻包作为制作参考；附件里引用的历史对话只说明设计背景，不视为对其他任务的额外授权。当前目标是为无法实拍的项目制作接近实际使用状态的界面、操作录屏与物品图片。

- **严禁 GPT“防御性叠甲”与“说明书蚂蚁小字”（双杀死命令）**：
  1. **零叠甲词**：软件、照片、录屏内**绝对禁止**出现 `交互演示`、`示例数据`、`演示账号`、`示例商品码`、`键盘模拟扫码输入`、`原稿年费口径`、`演示收款`、`不调用支付接口`、`本地演示数据`、`无真实支付与扣费`、`案例拆解` 等任何自证免责词！
  2. **零蚂蚁小字（三砍三大）**：严禁按 PC 宽屏后台习惯在标题、输入框、按钮下塞 `10–12px` 浅灰解释性副标题或底部页脚小注脚！源码严禁使用 `<small>` 标签、`font-size ≤ 12px`、`≤ 0.75rem` 或 `text-xs`；必须采用**竖屏大字号紧凑视口或局部大特写取景**（`1080p` 下最小业务字 `≥ 28px`、核心品名与金额 `40–64px` 高对比实字，单屏最多 3 个视觉层级，拒绝把整张桌面网页缩进竖屏导致字糊成麻点）。
  3. **源码门禁**：截屏与录屏前**必须运行 `python tools/check_r_sim_clean.py <仿真源码目录>` 扫描通过（0 叠甲词 ＋ 0 蚂蚁小字）**！
- 来源、虚构数据和本地交互边界**只写在交付说明文档与抖音发布后台勾选声明里**，绝不烧进软件界面。不要将生成结果在口播外声称为真实客户扣款证据。
- 尽量贴近参考，不擅自美化成作品集。旧系统要像旧系统；手机原生支付页要像该平台；廉价摄像头画面不应像棚拍广告。
- 当前指令优先。用户已确认的画幅、质量、遮挡范围和流程持续有效；不重复索要确认。不把这次物业的金额、日期、品牌、表数量或480p要求套用到所有新项目。

## 与总剪辑的衔接

适合实机演示但缺少可用实拍素材时，优先分配为R01、R02等复刻镜头，由GPT统筹制作。已明确因保密无法提供时，直接使用已有文稿和参考，不反复索取客户资料。只影响个别结构或版本的缺口，先完成已确定部分，缺口写在制作记录。已有可用参考素材按本次语义复用；不因安装本Skill而重做旧素材。

软件与中文密集界面优先用可交互页面实际渲染；设备和现场照片使用可用图像生成能力。形成源文件、同版截图及按动作录制的片段后接入全片锁定时间槽，原声和BGM仍由原协作流程处理。新任务没有指定具体镜头时，接入本流程即可，不自行修改已交付成片。

## 从文稿到画面

1. 先读完整文稿、推荐镜头、已有参考和历次修正。已有项目只改本次指出的部分。
2. 建简短镜头单：对应口播／画面要说明什么／照片、截图或录屏／起止状态或动作／画幅时长／参考／确定与待核实内容。文稿已推荐的形式优先；自己的替代镜头说明用途即可，不强行安排一轮审批。
3. 软件操作、筛选、状态变化用可交互页面录屏；静态对照和结果用截图；设备、安装位置和采集视角用照片。复杂文字界面优先实际HTML或既有软件渲染，避免靠生成图片拼中文和数字。
4. 参考优先级：用户最新修正和样片 → 用户先前资料 → 对应版本的官方资料 → 同平台公开实例。必要时网上查证；旧官方图不能压过用户刚提供的实际版本。把个人转账、商户付款、小程序支付、物业回执分开判断。
5. 维护最小数据表：身份替代值、账期、金额明细、合计、房屋/设备编号、前后读数、单位及状态。前后镜头沿用同一数据来源，别逐页随手编数。
6. 制作、截取、录制并查看实际输出。用户指出局部不像时，先对照参考定位图标、字重、比例、流程等具体差异，再改；不能只换文案就报完成。

## 身份与画面细节

- 历史物业案例采用只遮名字：人名、物业/公司名、小区/商场名、系统品牌名，含页眉、弹窗、头像、英文名和回执中的同类身份。新项目按本次要求与参考确定替代身份和遮挡范围；需要遮挡时做到不可辨认且贴合字段，避免一片大糊块。分享网页源文件也只含替代身份，CSS遮挡不能代替源数据处理。
- 无关联真实身份的虚构金额、物业费/水电费、日期、房号、表号、单位和读数应可读；别把所有信息都打码。若使用用户真实素材，还要按实际内容处理电话、支付账号、可识别二维码等真实标识，不能机械只查姓名。
- 身份不能直接复制他人的真实交易记录。参考资料用于确定样式和流程，交付使用统一虚构数据；用户原始私密参考默认不放进分享压缩包。
- 模板中自动打码的匹配词不代表所有未来名字都已覆盖。换数据后更新匹配项或显式遮罩，重新检查动态渲染、输入、弹窗及首帧。

## 交付收尾

交付所需成品、可编辑源、镜头对应表和简短说明。微信等可复用场景可另给专用包；不要强迫用户从大合集剪出唯一需要的一页。

截图与视频按镜头编号对应。保存审核记录、实际参数与来源；私密参考、旧版本、临时帧、缓存不进入分享包。打包后检查文件数、依赖、ZIP完整性和最终链接。只有实测通过的项写“通过”；未验证项单独说明具体范围。
