# 两轮核审：查不合理之处

两轮都看实际产物，不能把运行两遍同一个测试当两轮审核。每轮保留“发现 → 修改 → 复核结果”；没发现问题也写明检查范围和依据。第二轮改动后复验受影响镜头，避免报告通过但压缩包仍含旧文件。

## 第一轮：制作自查

逐镜头对照文稿、数据表和参考，重点问：

1. 业务动作成立吗？付款、返回商家、回执是否混页？已缴和待缴状态是否前后矛盾？按钮是否真正产生预期本地状态变化？
2. 数能对上吗？费用合计、账期、房号、表号、上期/本期读数和计量单位是否一致？
3. 属于同一设备/软件年代吗？字体、密度、系统图标、手机边框、胶囊、返回按钮和状态栏是否与参考吻合？
4. 物品能这样安装、拍到这个视角吗？结构是否合理？低清是否符合采集源且仍可读？
5. 应遮名字是否在首帧、交互后、弹窗和结尾都已遮住？金额等应展示字段是否被误遮？
6. 实际视频有无黑帧、空白、错比例、裁掉的按钮、突兀鼠标/hover？截图与导出视频是否同版？

完成尺寸/时长/编码/解码、页面关键动作与压缩包CRC等必要检查。只记录实际做过的项目，不把源代码自检当视觉通过。

## 第二轮：独立挑错

以第一次看成片的物业工作人员、手机用户或剪辑师的角度，重新找最可能露出不合理之处的位置。工具允许时由另一代理独立审阅，给它实际参考和产物，不先灌输已经正确的结论；没有代理也要换检查顺序，先从结果倒推动作。

- 重点复查支付末页、状态栏、名字遮挡、设备读数、最密集界面和所有切点。
- 对照参考按整体构图→平台控件→文字/数字→头像/信号/电量→运动/跳转逐层看。不能只判断挺像。
- 正常倍速审动态，再检查切点前后相邻帧；没有完整回放时明确写抽帧和解码检查，不称全片已逐秒看完。
- 查交付：是否混私人原片、旧版本、错误链接、缺失依赖、重复进合集或没有最终成品。
- 区分本次用户指定的例外和普遍规则，避免把某版微信按钮、某笔金额和某项目尺寸固定到所有后续任务。

## 通过条件与记录

业务矛盾、身份暴露、金额错误、图标/按钮用错、黑帧、结构不成立和打包遗漏均先修再交。参考不足或工具未验证的部分不能写成通过；具体说明限制，按用户范围继续完成可确定部分。

记录字段：镜头/文件、对照依据、不合理点、改动、复核方式与结果、尚未核实项、审核人或代理、实际检查时间。把最终文件清单与哈希留在交付记录中，避免审的是A、发的是B。
