# 创作者动作提示词与连续性调研

检索/阅读：2026-11-13。以下均是创作者本人、制作团队或其作品账号发布的公开材料，不把搜索摘要当成完整教程。本轮读取正文、公开帖文、提示词和制作者说明；**没有完整播放这些网页嵌入的视频，也没有复现实验**。作者报告的成败与本项目已核验结果须分开。

证据分级：A＝第一手长文，公开操作/提示词及失败；B＝第一手文字说明，过程简略或没有对照；C＝仅定位到入口，不能采纳技术结论。全部方法仍须在LibTV当前入口实际验证。

## 可收入方法库的7项

### C01｜Curious Refuge：改变机位不能顺带改掉动作

- 作者：Mable Huang / Curious Refuge制作团队。
- 标题：[How to Change Camera Angles With AI | Tutorial](https://curiousrefuge.com/blog/how-to-change-camera-angles-with-ai)
- 日期：页面标Sep 18，正文未显年份；不以抓取时间代替发布时间。
- 已读：全文、3种方法和示例提示词；未播放内嵌对比视频。证据A。
- 发现：团队报告自动换角度时洋葱变鸡蛋，加时间码后仍有橙子变彩椒。其较可靠方法是先定剪点，再导出3–5秒原动作，逐段指定新机位。
- 可用法：每次只解决一个连续动作/一个替换角度，角色、道具和动作参考明确指定。
- 边界：时间码改善安排，不能保证物体守恒；文中说仍需反复生成。

### C02｜Curious Refuge：真实表演或深度视频可以提供运动骨架

- 作者：Mable Huang / Curious Refuge制作团队。
- 标题：[How to Use AI in a Hybrid Filmmaking Workflow | Tutorial](https://curiousrefuge.com/blog/how-to-use-ai-in-a-hybrid-filmmaking-workflow)
- 日期：页面标Sep 22，正文未显年份。
- 已读：完整灰盒拍摄、首帧设计、原片/深度参考对比及失败段落；未播放视频。证据A。
- 发现：先拍表演与调度，再改世界；作者测试中深度参考有时改善运动，但脚部仍有问题，换成酒杯后咖啡杯又会返回。
- 可用法：复杂手脚接触优先录一个简易动作参考，再指明只借动作、另图定义造型。
- 边界：不是精确动作复制；造型、光照与表演仍可能漂移。

### C03｜Curious Refuge：2D动画也能有明确动作链与空间因果

- 作者：Mable Huang撰文；教程复盘Albert的实际制作。
- 标题：[Here’s the Best AI Workflow for a 2D + Live Action Film](https://curiousrefuge.com/blog/the-best-ai-workflow-for-a-2d-live-action-film)
- 日期：页面标Sep 29，正文未显年份。
- 已读：完整长文，包括动作时间线、参考职责、2D旋风失败与后期修正；未播放内嵌片。证据A。
- 发现：按时间排列连续动作，区分环境片、人物表和道具表。团队用卡通运动、拖影保持2D风格；旋风参考太具体反而变成平面贴图滑动，改成角色参考加动作描述。
- 可用法：让字形、纸片、墨迹成为运动主体；先规定发生关系，再选视觉材质。
- 边界：动作帧仍可能丢道具；团队采用局部合成而非无止境全段重抽。

### C04｜Tim Simmons：给模型实际运动，不只写一串编舞动词

- 作者：Tim Simmons / Theoretically Media。
- 标题：[TheoreticallyMotion Control](https://theoreticallymedia.com/tools/theoretically-motion-control/)
- 日期：页内标最后测试July 2026，并非发布日。
- 已读：工具作者完整说明、控制项、试验与局限；未运行工具或播放视频。证据A。
- 发现：作者把原片转换为姿态加深度，帮助复杂运动、接触和出入画；人物颜色用于指代不同角色。
- 可用法：当同一句提示词反复失败，升级输入为运动参考，指定它负责动作、风格参考负责外观。
- 边界：作者明确说同样提示词下模型偶尔完全忽略视频；接受视频参考不等于所有平台都支持这些控制。

### C05｜Kazi Ahmed：首尾帧之间要有可见原因

- 作者：Kazi Ahmed / Kazitorials。
- 标题：[No Rehearsals: From Character Sheet to Cinematic Scene](https://www.kaziahmed.net/kazitorials/character-sheet-to-cinematic-scene)
- 日期：正文未见明确发布日。
- 已读：参考输入职责、点火/吹灭案例、跑步和驾驶提示词、失败诊断；未运行配套ComfyUI工程。证据A（具体执行教程，尚未独立验证）。
- 发现：匹配构图的首尾图之间，写拇指动作→点火→脸被照亮，拒绝全局曝光渐变。跟拍人物时须让背景产生视差，否则会像跑步机。
- 可用法：桥消失要写从哪里开始、按什么顺序撤掉承重、人物如何停步；不能只写“首帧有桥，尾帧没桥”。
- 边界：页面说明部分实例是重构方案，不能把所有可复制提示词当成已证明成功率的实验。

### C06｜Martin Nebelong：把控制需求放进图像/空间输入

- 作者：Martin Nebelong。
- 标题：原帖无专门标题，以“Things are moving fast these days!”开头。
- 链接：[作者公开制作帖](https://www.linkedin.com/posts/martin-nebelong_art-ai-activity-7221482288482512896-Wslo)
- 日期：页面仅相对时间，未核绝对日期。
- 已读：作者完整帖文；未播放所附片。证据B。
- 发现：作者用自制模型、布光和构图提取首尾帧，再交给视频模型，以获得比纯文本更大的控制。

## 给本项目的综合判断（研究推论，不是作者共同保证）

1. 提示词只是控制的一层。连续动作难点若在接触、速度、遮挡，继续加形容词往往不如补中间关键姿态、视频动作参考或分层制作。
2. “单一核心事件”不是“画面必须保守”。桥由代码逐段形成或消失，本身可构成一个足够强烈的事件；将主体、变化方向、触发规则、结果保留下来，其他表现可以大胆。
3. 连续性应保存身份、空间、方向、速度和因果，不能只保存首尾长相；时间码只描述意图，仍需看真实片段。
4. 不默认3D：2D剪影＋字形桥、纸张/墨迹变形、平面拼贴＋实拍、分层光照合成，都是可研究媒介。它们是否适合本期，需要依据口播和品牌语气选择，不因作者用过就照搬。
5. 对“代码之桥”要区分主观误解与最终观点。若桥只在学会代码后出现，容易被观众理解为“必须先会代码”，与本期开场反问/后文零代码接单相冲突。可以明确把第一状态当成观众的旧信念，再安排视觉反转；具体反转应由主导演根据真实口播槽决定，不能悄悄改用户口播。
